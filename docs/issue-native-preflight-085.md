# 0.8.5 原生子任务前置条件检查（2026-11-04）

用户截图中 Claude 严格模式可用，调用申请了原生子任务，但会话协作关闭，执行才返回 `native_collaboration_disabled`。现有执行拦截正确，问题是界面仅检查通道/模式，创建调用时也未校验协作条件，因此生成无法执行的已批准卡。

修复：复用后端原生启动预检，在创建原生调用时检查实际根任务策略；失败不保存消息、审批或配额。保留执行前再次检查，覆盖创建后策略变化。前端根据已保存策略禁用不满足条件的“逐次审批”，提示先开启协作/设置深度并发，或保持子任务关闭发送普通严格消息。总 Token 或分模型预算不支持原生子任务时也提前提示。不自动开启协作、扩大限制、变更用户的调用快照或执行消息。

验证：HTTP 原子拒绝、普通严格消息不依赖协作、有效配置可创建待审批、同键重试与重放、策略变化仍在执行前拒绝、前端状态检查。真实账号与模型不用于该修复测试。安装/发布沿用用户既有授权，通过后更新并保留原配置。

旧冲突调用的执行按钮也会禁用并显示原因，已同意卡增加“撤销此调用”，复用原有撤销审批接口。保留历史消息、审批及协作策略，不擅自重写快照或替用户开启协作。单次安装时只允许已证明未启动、无活动预留且原生条件不满足的已知排队记录保留；其他运行/未知/可执行排队或自动阶段仍阻止升级。
