流程：开启协作扩展 → 写计划，或由主 Agent 拆分 → 按依赖逐个分派子任务（每个单独审批）→ 全部完成后汇总交给一个 Agent（再审批一次）。

## 做了什么

- **开关**：沿用策略中的 `collaboration_enabled`，默认关闭。页面“协作计划”栏可以开启或关闭；保存时会合并当前策略，生成新的版本。开关关闭时：
  - 保存计划被拒（`collaboration_disabled`）；
  - 分派被拒；
  - 已生成的子任务调用在执行门处被拒（原有规则）；改策略本身也会撤销未消费的审批。
- **计划**（契约 `agenthub.collab`）：
  - 1 到 5 项，每项一个 Agent、一个自足的目标，可以写依赖（只能依赖排在前面的项）。保存在表 `collab_plans` 和 `collab_items` 中。
  - 两种来源：
    - 手写；
    - “请主 Agent 拆分任务”：在输入框中填入固定请求 `PLAN_INSTRUCTION`，作为一次普通调用，照常审批和计入预算。主 Agent 回复后，点“读成协作计划”，按 `1. agent: 目标 (after 1)` 格式读回，编辑后保存。不认识的 Agent 会被标出，保存时 422。
  - 由主 Agent 提议的项，分派出的任务记为 `auto`；手写的记为 `user`。
- **分派**：`POST …/plans/{id}/items/{n}/dispatch`。
  - 每一项是一个深度 1 的子任务调用：第一次分派时创建子任务（这时检查开关），重试时复用。每次都生成待审批调用，绝不自动执行。
  - 只有它依赖的项都完成后才能分派（`dependency_pending`）。这些结果以交接框附在前面，审批卡完整显示。
  - 进行中或已完成的项不能再分派（`item_in_progress` / `item_done`）。确认失败（被拒、失败、取消、超时、作废），或已结束但没有可交接的回复时，可以重试 1 次，超过返回 `retry_limit`（每项最多 2 次）。
  - **状态未知**（`unknown`）显示为“状态待确认”，不算失败，也不能重试：原调用可能仍在运行，名额保留，不会被自动释放。分派会被拒（`item_unconfirmed`），不创建调用，也不启动适配器。只有经现有的恢复或人工裁决确认它已结束后，才按结果处理：裁决为失败后可以重试，裁决为成功且有回复则视为完成。
  - 执行时，原有限制照常生效：子实例总数和并发数、深度、预算、停止和暂停。
  - 项的状态由它子任务上的**全部**调用推出，最新一次为准，包括人工裁决产生的重试调用。状态有：待分派、待审批、执行中、状态待确认、完成、已结束无回复、失败。状态不另外存储。
- **汇总**：`POST …/plans/{id}/collect`。全部完成后，生成一个根级调用，把各项结果作为交接框（合计不超过 4 万字），加上固定的汇总请求（`COLLECT_INSTRUCTION`）交给所选 Agent，待审批。
- **嵌套**：Hub 只创建深度 1 的子任务，子任务的回复不会再被读成计划。
- **页面**：
  - “协作计划”栏：开关、请主 Agent 拆分任务、写协作计划、最新计划各项的状态、依赖和分派或重试按钮、汇总按钮。
  - 回复旁增加“读成协作计划”。
  - 子任务调用卡显示“子任务 #n（计划 P，第 k 次）”。

## 验证

- `tests/test_collab_plan.py`：计划校验，以及宽松读回（重新编号、丢弃无效依赖、标出未知 Agent）。
- `tests/http/test_collab.py`，在双 Agent 桩上运行：
  - **开关**：没有任务或开关关闭时，不能保存计划；开关关闭后不能分派，也不创建调用。
  - **完整流程**：依赖未完成时分派被拒，且不创建调用；第 1 项是深度 1 的待审批调用，批准后完成，再分派被拒；第 2 项发送“第 1 项结果的交接框 + 自身目标”，Claude Code 收到的正是这些；全部完成后汇总调用带上两项结果；子任务记为 `user`。
  - **重试**：失败（被拒）后可以重试 1 次，第 3 次被拒（`retry_limit`）。
  - **状态未知**：第一次调用为 unknown 时，项显示为“状态待确认”，且不可分派。再次分派被拒（`item_unconfirmed`），调用数不变，适配器没有启动，名额仍被占用。人工裁决为失败后，项变为“失败”，这时才能重试，生成第 2 次的待审批调用。
  - **限制**：子实例总数为 1 时，第 2 项执行被拒（`max_subagents_total`），适配器启动次数不变。
  - **主 Agent 提议**：回复读回，未知 Agent 被标出且不能保存；保存后分派出的任务记为 `auto`。
- 受影响的已有测试一并运行，共 373 项通过。
- 页面在 `p4-collab-demo`（8180）上检查过一次：开启开关 → 写两项计划（第 2 项依赖第 1 项）→ 分派并批准第 1 项 → 第 2 项才可分派，发送内容带第 1 项结果 → 两项完成 → 汇总交给 claude-code（待审批，带 2 段交接）。控制台没有错误。

## 已知限制（真实运行中观测到，原因未知）

- **Claude Code 的模型和回合数**：在 `--max-turns 1` 下，Claude Code 2.1.308 有时会报告 `num_turns=2` 和两个模型（`claude-opus-5-5`、`claude-opus-5`）。
  - 账本按规则记为 partial（`multi_model_usage_unverified`），不把各模型的用量相加；
  - 判定脚本单独记录回合数异常。
  - 两次运行各出现一次，原因未知。
- **Claude Code 安全防护拒答**：即使是无害的固定汇总请求，也可能被 CLI 以 API 错误拒答（`is_error`）。这时 Hub 的处理：
  - 调用记为 failed，名额释放；
  - 用量记为 partial，CLI 的错误消息保存在执行记录中。

  这些处理都是正确的，无需另外排查。
