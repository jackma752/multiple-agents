## 执行与通过条件

1. 使用已配置 DeepSeek Flash、生产 HTTP 适配器、真实公开网络来源、API/阶段审批/Worker。隔离新库与目录，不复用用户任务或旧在线账本。主写与审阅使用相同模型并如实标记，不称独立专家评审。
2. 采用 1 篇核心论文的 project 流程，覆盖多源检索/完整筛选、取得非空全文、精读、审阅、研究候选、非空成果导出、项目与演示实验版本保存、重启及零额外调用重新导出。候选创新性仍是 unverified，演示实验不得冒充论文复现。
3. 本轮总额度 100,000 Token，先手动通道验证最多 2,000，研究阶段最多 98,000、单次预留 20,000，研究最多 15 次调用，加手动验证共不超过 16 次。均为启动前预留与记账约束，不宣称 provider 硬截断。预算不足、未知状态或超过 25 分钟即暂停并保留证据，不无限重放追通过。
4. 不接受空成果、跳过全文或吞掉校验错误当作通过。引文仍按已提供材料精确核对；遇到产品错误先离线复现修复，再仅接续已授权的未完成步骤。原失败证据保留，不放松审批、预算、来源或质量标签。
5. 成功后保存实际结果、哈希、测试和提交；核对 main 工作区与远程变更后合并，不覆盖外部修改，不强推。只推 main 和本轮发布所需的明确标签，不推所有分支/标签。
6. 更新 GitHub 源码与 Windows 发行包：冻结程序已验证的 0.8.3 构建可复用；若运行时代码再变，则重新构建并核验。上传仅安装包、便携 ZIP、SHA256SUMS，不上传证据、凭据、数据库或研究输出。

Codex 的固定 CLI 仍有钩子故障放行，严格入口拒绝为预期边界，不作为本次研究流程的可用通道；既有 Claude 在线通过证据保留。本轮不重复其模型请求。完整流程通过不等于数学正确性、方案新颖性或真实实验已认证。

## 在线发现后的修复范围

10 次真实调用累计 97,683 Token 后停止，没有足够预留再发调用。原自动下载失败，补充官方同文献 URL 后全文通过；33/33 引文与存档导出通过，但审阅发现材料和数学问题，质量仍为 needs_review，不能合并/发布。发现 `phase_read` 在缺失资料且没有新片段时直接 break，会同时跳过现有资料可修正的数学/引用问题。离线修复为仅允许这些点名问题的受限修订；没有新资料时禁止增加单元，后端保留旧缺口并禁止把 incomplete 提升为 complete。纯材料缺失仍不追加改写调用，轮数/审批/预算保持。

修复先做离线验收并提交，不扩大既定 100,000 Token 额度。用户随后明确追加 40,000 Token，仅修订与复核，已用独立账本执行 2 次、37,685 Token。原流程质量 needs_review 和原 passed=false 保留；局部修订与复核 passed=true。发布软件功能修复时必须同步声明这一差别，不能把原科研内容质量改称全部通过，详见 [实录](online-release-0.8.3.md)。
