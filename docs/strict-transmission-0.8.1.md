## 严格模式实际状态

论文总预算缺少单次预留的问题已在上个提交修复；新建/接续、预检与预算门禁均有回归。本版进一步在论文预检返回 `mode_admissions`，逐一检查主 Agent 和审阅 Agent 的所选模式。不可用时先说明原因，拒绝创建任务，不再让用户去手动运行一个当前通道无法放行的严格回合。底层 Worker 的独立准入/审批/预算复查保持。

新建研究默认选择严格模式可用的真实通道，当前为 DeepSeek。已知 API 默认模型自动显示其已配置 ID，使“关闭推理”等选项可用；默认推理强度不变，用户明确选择后才进入批准内容。更换通道时清除不适用的模型/强度，审阅同通道沿用主模型，用户之后手动选的通道和执行模式不会自动改动。离线桩有明确说明。

## 传输实现与实测

- 现有 `StreamSink` 已按 0.2 秒/2000 字符合并输出，本版保留。数据库事务成功提交后，只向同进程订阅者发唤醒提示，SSE 按原游标重新读取已提交事件；通知不携带文本、不改变授权或执行状态。回滚不通知，连接结束解绑，多客户端各自接收。其他 Worker 进程保留 0.5 秒数据库轮询兜底。
- 一页内的 SSE 帧合并成一次应用层输出，保留每条事件的 id、顺序、重连与鉴权，不等整个模型任务完成。
- 论文 GET 请求声明 gzip，记录响应体的 `wire_bytes`/`encoding`；解压后提供与原解析器相同的字节内容。压缩体和解压体分别受原大小上限约束，损坏、截断、未知编码或解压膨胀均拒绝；每次重定向仍检查资源权限，TLS 检查不变。URL、规则哈希与模型输入不因此改变。

对旧版 `e57089e` 和新版各启独立的本机开发服务，只创建固定测试消息，不创建 Agent 调用。每版 5 次，测“消息 POST 开始至 SSE 客户端收到新事件”：

| 指标 | 原版 | 本版 |
| --- | ---: | ---: |
| 中位等待 | 459.786 ms | 5.465 ms |
| 五个样本 | 459.786 / 475.105 / 476.290 / 455.569 / 457.535 ms | 7.054 / 5.465 / 5.644 / 5.200 / 4.612 ms |

一次真实 OpenAlex 查询返回 200、5 篇：gzip 响应体 **14,228 字节**，解压为 **85,143 字节**，体积少约 **83.3%**；本次请求 2.564 秒。这里比较同一响应的压缩/解压体积，没有把单次网络耗时当作稳定吞吐提升。上述改善不等于模型推理或生成速度提升；原在线过程的推理用量另在在线记录中如实登记。
