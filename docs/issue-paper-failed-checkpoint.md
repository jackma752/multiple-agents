# 已结束但讲解失败的研究按断点接续

用户在 2026-11-05 要求保留已完成的一半研究，从失败步骤继续。现有接续只接受停止的任务树；讲解失败后导出为 done 的任务没有入口，且失败 study 的 finished 标记会导致阅读阶段跳过它。

本轮契约与范围：

- 扩展现有用户专用 `POST /api/papers/{id}/continue`，接受已结束的 study/proposal/project 中有可重试讲解或方案生成步骤的任务。GET 任务增加只读 `retry_checkpoint`（无可重试步骤时为 null），包含阶段、目标论文和剩余次数/Token；旧请求字段不变。
- 新会话、任务树、阶段采用当前适配器绑定；请求、资源规则、模型和单次预留沿用原授权。只使用原剩余次数与 Token，禁止重置或放宽预算。用户监督模式仍需明确边界同意。进行中或状态未知的调用阻止接续。
- 原任务、调用、失败记录及成果保留。复制已成功资料和结果，只重新运行失败讲解及其下游；缺全文且用户已选择继续的论文不重新索取。只缺材料、数学质量待核查不触发重试。
- 保留失败步骤的调用 ID 供累计用量审计。已保存的结构有效引文修复种子，在相同全文选择和输入哈希核对后带入新步骤，只修错误引用，重新执行全部结构/来源校验及审阅；不得把恢复草稿直接标成成功。
- 页面提供“从失败步骤继续”，明确保留内容、剩余额度和新调用会计费。点击并确认前不创建阶段、不调用模型；重新导出仍不重试模型。

验证：离线端到端复现 done + 零讲解；恢复后不重复检索/筛选/全文/关联提取；混合成功/失败论文只重试失败目标；仅引用修复保留正文；新阶段绑定；预算与来源/审批门禁；双击幂等；成功任务/仅缺全文拒绝；原记录不变。真实模型生成质量不在本轮离线验证中声明通过。

## 已执行验证

- 论文全组 + HTTP 自动阶段/预算准入：`277 passed in 105.57s`。新增 12 个断点用例包含零正文、仅方案失败、混合核心、引用修复、登录/用户监督同意、进行中/未知调用和耗尽次数/Token 拒绝。最初两个测试准备未选择全文继续、把监督同意放在错误接口，修正测试准备后本轮全组通过。
- 实际论文页面脚本语法及 renderHead 函数 11 项离线检查通过：展示两篇/23 次、转义、渲染和取消确认均不 POST、确认携带监督同意、接续链接与成功任务无重跑按钮。不是浏览器或真实模型质量验收。
- 对本机实际研究仅只读规划：read、2 篇失败讲解、剩余 23 次、无总 Token 上限、1 个保存的引用修复种子；未创建接续、未修改研究、真实调用 0。用户数据不入仓库。
