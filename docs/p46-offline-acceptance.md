# P4.6 用户离线验收

2026-10-26。代码已准备；本页是操作指南，不代表用户验收已经完成。全程使用模拟器，不调用真实模型、不消耗模型额度。先体验单 Agent 自动与额度恢复，再验证协作。实际模型的工作质量及真实额度格式另行验收。

## 1. 启动后台

打开 **PowerShell**，逐行执行。端口使用 8186，与原来的 8182 演示分开；若已有 8186 服务，先确认并停止那一个服务，不要关闭所有 Python 进程。

```powershell
Set-Location 'E:\plug\agent-hub\.worktrees\p46-autopilot'
& 'E:\plug\agent-hub\.venv\Scripts\python.exe' tools/demo/serve.py --host 127.0.0.1 --port 8186 --adapter multi --appserver-stub demo --claude-code-stub autopilot --data-dir var/p46-user-demo/data --files-root docs
```

看到 `Uvicorn running on http://127.0.0.1:8186` 后保持窗口打开。浏览器打开 `http://127.0.0.1:8186/chat`（根路径 `/` 返回 404 不代表后台失败）。默认开发 token 为 `dev-user-token`，仅本地演示使用。

以后恢复这次演示，运行完全相同的命令，尤其保留 `--data-dir`。切换数据目录相当于另开一套记录。

## 2. 先手动成功一次

1. 新建会话，Agent 选择 `claude-code`，执行模式选择“严格模式（离线模拟）”。
2. 输入 `演示自动执行前的手动验证`，发送，再点“启动本次调用”。
3. 等待固定回复 `Offline stage step completed.`。右栏“自动执行”应显示该 Agent 在严格模式已跑通。

这一步只用于启用相同模拟配置的自动阶段。真实接入不能借用模拟记录通过检查。

## 3. 一次授权，自动修复并收口

右栏“自动执行” → “设置自动执行”或“开启新阶段”，填写：

| 字段 | 内容 |
|---|---|
| 阶段目标 | `DEMO_RETRY` |
| 完成标准 | 模拟错误修复后返回完成回复 |
| 执行边界 | 严格模式 |
| 计划 | 不拆分 |
| 使用的 Agent | 只勾 `claude-code` |
| 主 Agent | `claude-code` |
| 审阅 | 不审阅 |
| 调用上限 | 12 |
| 修复次数 | 3 |
| 额度恢复自动继续 | 勾选 |
| 命令前缀 / 文件修改 | 留空 / 不勾 |

点“按规则自动执行”，阅读阶段确认框并确认一次。模拟器第一次故意失败，下一次识别修复请求并成功。预期：无需逐卡批准，两次调用都注明阶段授权，修复计数 `main 1/3`，最终显示“阶段已完成”及总结。

阶段完成后不会自行开启下一个阶段。模拟器的固定回复只用于验证流程，不证明模型真的能解决需求。

## 4. 额度等待后自动继续

开启新阶段，沿用上一组规则，将目标改为 `DEMO_QUOTA`。预期：第一次调用报告模拟限额，进入“等待额度恢复”，约 5 秒后自动继续并完成，普通修复次数不增加。

可以再用一次这个目标体验暂停：看到等待状态立刻点顶栏“暂停”，刷新页面，确认仍为“已暂停”；点击“继续”后才会恢复。不要为了这个演示等待真实额度刷新。

真实错误没有可靠恢复时间时，使用表单的“首次检查间隔”，默认 5 分钟；仍限额就翻倍，最多 60 分钟。这与本演示提供明确的 5 秒恢复时间不同。

## 5. 按依赖自动执行并汇总

为先看完整流程，可全部使用 `claude-code`：开启新阶段，计划选择“请主 Agent 拆分”，目标写 `演示两项依赖任务并汇总`，使用的 Agent 仍只勾 Claude Code。此桩会返回一个两项依赖计划，调度器依次执行并汇总；拆分、两个子任务、汇总均无需逐次点击。

如需混合 Codex 与 Claude Code：先手动跑通 Codex 一次（模拟工具卡可拒绝，让回合正常完成），再手写两项计划：#1 Codex、#2 Claude Code 依赖 1。自动阶段选择“使用当前计划”，两者都勾选。要体验工具自动允许，在命令前缀中填写 `dir C:\stub`；留空则自动拒绝。界面“完成”指模拟调用的流程完成，不代表真实需求已实现。

Hub 的并发、累计子任务、调用和 Token 上限仍然生效；若之前的演示耗尽了某个根任务的配额，可新建会话再验证，不会自动扩额。

## 6. 结束与留存

检查阶段总结、调用卡的授权来源、原记录和累计用量。未执行的阶段可点“停止”；进行中的调用只能按适配器返回的中断结果认定是否停止。

所有阶段结束后，在运行后台的 PowerShell 按 `Ctrl+C` 停服。需要验证服务重启恢复时，也用同一数据目录启动；不会要求再次点击每张旧审批卡。用量或执行状态为未知时，应先核对记录，不重复启动。

本轮未替用户完成 P4.6d 人工验收；真实额度恢复、真实自动工具执行仍未验证。全部代码只在 `feat/p46-autopilot` 分支，合并 main 另行决定。
