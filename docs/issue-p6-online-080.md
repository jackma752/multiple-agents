# 0.8.0 在线验收

2026-11-02，用户在当前对话要求“帮我做一下在线测试”，作为真实外部文献检索、公开 PDF 下载与现有模型通道的小规模测试授权。独立分支 `test/p6-online-080`，基线 `0704707`。不修改现有账号、安装、研究任务、main 或远程仓库。

代表性主题：检索增强生成的评测方法。先零模型检查四个来源及网络；随后经标准 Hub API 的审批/阶段/预算链路运行 DeepSeek 小任务，目标 2 篇，核心精读 1 篇，候选每查询每源 5 条，局部补读/修复最多 1 轮。模型阶段最多 16 次、Token 上限 50,000，另有一次最小通道验证；不自动提高预算或更换付费服务。同一模型承担阅读和审阅，不当作独立模型交叉验证。

仅使用公开材料；无本地研究目录权限、无代码执行、无远程主机。若缺全文，先检验补充关口，再明确按现有公开材料继续，记录阅读深度。导出与实验记录使用演示数值验证，不冒充真实复现实验。原始在线证据留在忽略的 var，只提交脱敏结果和证据文件哈希。

验收分别记录：网络/来源可用性、真实模型与用量、完整流程与错误处理、引用/片段关联、数学讲解的人工抽查、导出/实验版本、重启与重导出零额外调用。失败必须保留，不把降级路径写成原路径通过。

在线发现：仅填写总预算时，严格预算因缺单次预留拒绝启动。先补公共 API 字段 `token_budget_per_call`（可空正整数），预检要求设置总预算时同时填写且不超过总预算；明确预留不是 provider 端硬停止。新任务将其保存至已有 Policy，接续保留原预留，剩余额不足下一次预留则拒绝接续。旧无预算请求/哈希保持，不降低底层预算校验。测试本次预留 15,000，总预算仍 50,000，不提高原上限。

第二项发现：首批 20 篇筛选，三个真实回复均缺相同 ID。两次修复后如实 blocked，不放宽完整性要求。校验错误增加具体缺失 ID，以便既有修复提示准确指出缺项。原多源任务不继续追加修复。扣除所有已知真实用量后，剩余预算用于单篇/单源/无审阅的 study 小任务，选择不启用推理，最多 7 次调用；不能把此降级验证写成原多源项目全流程通过。

第三项发现：模型把多个词组和同义词都组合为 arXiv AND 查询，三个查询均空，连明确命名的 RAGAS 也未召回。增加一次确定性兜底：仅全部来源无条目、原 arXiv 查询成功且均空时，取首个多词查询的第一个词组再查一次；年份、来源、篇数和筛选主题不变，保留原查询及 broader 标识，不因 HTTP 失败扩大查询。不新增模型规划、不循环放宽、不改变旧成功步骤键。已完成的无结果任务保留，后续单篇验收重新从剩余总额度计算预算。
