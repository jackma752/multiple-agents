## 2. Paper-Agent 实际流程及借鉴点

| 环节 | 已读实现 | Hub 的接入方案 |
| --- | --- | --- |
| 请求与主图 | 请求进入运行服务，主图串联搜索、阅读、分析、大纲、写作和回复；存在阅读检查点时可从阅读入口恢复 | 保留这些业务阶段，每步挂到 Hub 的调用、工具或产物对象；不启动第二套常驻调度服务 |
| 搜索规划 | 角色输出子主题和检索条件，检索服务统一多来源结果 | 输出可校验的检索计划，用户约束由后端落实；关键词不能扩展授权来源 |
| 候选获取与筛选 | 三来源连接器；按来源平衡候选，再用模型批量判断相关性。筛选失败或无法解析时保留整批 | 搜索多于目标篇数；记录来源、覆盖与排除原因；筛选失败标为未筛选，不能宣称都相关 |
| 阅读 | 先摘要评估，再统一选深读论文；并发阅读、下载/解析、抽取、核查和按论文保存状态 | 把摘要/全文/核查状态分别建模，未取得全文的论文不能显示全文已读 |
| 分析 | 按子主题综合，再形成全局分析；全局 JSON 分析最终失败会阻止写作 | 保留分层结构；方法、数据集、结论、局限及研究空白与证据分别关联 |
| 大纲 | 结构化章节、前置内容和证据字段映射；模型不可用时可生成备用大纲 | 章节绑定 evidence ID；备用大纲只能当草稿，不自动作为质量通过 |
| 写作 | 按小节执行补资料、起草、审阅、修订循环；构造时工具最多 5 次、修订最多 2 轮 | 借鉴有界循环；每次模型/工具都进入授权、预算和幂等记录，次数由规则控制 |
| 引用与产物 | 将分块标记归到论文，编号与参考文献由已有元数据生成；未知论文标记被移除 | 元数据驱动排版；未知引用必须留下质量问题，不能只去掉标记后把无依据论断交付 |
| 运行恢复 | SSE 发布进度；重启对账孤儿 running 状态；阅读检查点恢复保留已完成结果 | 复用 Hub 事件、运行核对和资料存储；补到论文/章节粒度，不承诺任意步骤自动无损恢复 |

## 3. README 与实现之间必须区分的内容

1. **向量能力不能按宣传推断。** 当前 `read_node.py:37` 的全文嵌入开关为 False；有效异步分支在关闭时保存分块并返回 chunks_saved。`WritingAgent.get_chunk_by_embed`（约 614 行）仍为占位函数，工具分派也返回未实现信息。存在向量相关依赖和其他代码，不等于当前默认流程已完成向量索引与写作检索的闭环。
2. **完成标记不能等同于审阅通过。** `WritingAgent.review_draft` 在审阅模型缺失或调用失败时有 passed=True 的路径；修订达到上限时也可 completed=True 且 passed=False。Hub 要拆分执行终态与质量终态。
3. **备用结果必须显式降级。** 搜索模型筛选失败会保留候选；大纲和写作可产生备用内容；全局分析失败则会停止。Hub 要统一展示这些不同结果，不能都叫成功。
4. **引用存在不等于证据支持。** 上游提取字段要求有效 chunk 标记、写作去掉未知 paper 标记，这有助于格式和身份检查，却不能证明每个论断与原文相符。
5. **核查覆盖有限。** 全文核查遇到长文会截断输入；失败会记录并可能触发重提取，最终仍可保留警告。Hub 应记录送审片段覆盖，缺失材料不能变成反证。
6. **重启恢复不能泛化。** 孤儿运行清理和阅读恢复有明确代码，不能由此推断全流程任意副作用可自动重放。我们的恢复设计须跟既有 unknown 状态一致。

这不否定上游的流程价值；应分别借鉴其专业分工，并改进我们自己的结果状态和质量门槛。

## 4. 学术提示词库的适用范围

该仓库主要是研究构思、文章章节、语言修改、摘要、计划/展示和文档问答的人工提示词清单；README 另外链接外部 Custom GPT，但仓库未提供该 GPT 的内部实现。本轮不将外部产品宣传当作可移植代码，也不验证其可用性。

原文明确提醒文献可能被编造。部分模型能力表述带有历史版本限定，不能拿来作为今天的接入能力表。它不提供检索连接器、证据存储、恢复、授权或质量评测。

适合吸收的是“把研究写作拆成具体任务”的分类；具体采用方法、模板契约、自行编写的示例和测试要求见 [提示词设计](p6-academic-prompts.md)。

## 5. 整合决策

采用「Hub 执行内核 + 论文资料/证据服务 + 版本化阶段模板 + 成果工作台」结构。只添加业务领域层，不嵌入上游独立后端、Vue 前端或另一套 API 密钥配置。LangGraph 并非整合前提；先用现有调度器的能力完成设计验证，需要时再单独比较引入成本。

| 对象 | 沿用 Hub | P6 待补内容 |
| --- | --- | --- |
| 研究任务 | 根任务、会话、阶段授权 | 检索协议、纳排规则、任务与语料版本 |
| 模型角色 | 适配器、模型绑定、快照和预算 | 阶段模板、结构化结果校验、prompt 版本/哈希 |
| 检索/下载/解析 | 后端用户身份、阶段状态、工具审计 | 有类型的资源授权；来源、重定向、路径、大小与输出限制 |
| 研究上下文 | 引用预览、摘要与结果交接 | 语料索引、证据 ID、位置、阅读覆盖与证据选择记录 |
| 执行恢复 | invocation 持久化、unknown 阻止重放 | 每篇/每章提交点、内容版本、缓存失效和幂等键 |
| 成果 | 现有本机服务和安装体系 | 原文/证据/综述联动、可见质量问题、Markdown/JSON 导出 |

原文、模型输出及检索结果不能作为授权来源。选定模板及渲染后的实际请求进入调用快照；模板改版不会悄悄改变已审批调用。跨模型续接要遵循适配器实际能力；不要求所有通道具备工具调用，文本通道可返回结构化动作建议，由内核验证和执行。

## 6. 功能范围、质量约束与成本

首版目标是资料可追溯的小规模叙述性综述/研究简报，不自动宣称系统综述、荟萃分析或原创实验论文。后几者需要另行明确检索协议、评价、统计或实验数据流程。

起步保留约 5 篇论文的默认值而非硬性产品上限；来源先 arXiv，页面允许查看覆盖不足；按后续用户明确需求，首版必须提供论文补充入口，接受上传、已授权文件引用或文件地址，并按两种缺失策略处理。向量检索后续评测决定，不强制配置 embedding；模型相关性筛选与分块检索是两件事，不能因暂缓向量库而取消内容筛选。

独立记录 execution_status 与 quality_status；质量状态建议 pending/passed/failed/unavailable/needs_review。关键引用缺失、证据矛盾、全文/审阅不足不能标成 passed。允许导出明确标识的未审阅草稿；关键质量问题未解决不得标为通过质量检查的最终综述。

引用元数据来自检索/资料库，不由模型自由生成。原文片段核对、paper/chunk 身份校验是程序检查；结论支持、比较公平与研究空白是语义审阅和人工抽查。缺少证据的空白仅可标为当前样本未覆盖或候选问题，不能断言整个领域无人研究。

调用量需按步骤估算：假设 5 篇论文、3 子主题、4 正文章节，规划 1 + 候选筛选 2 + 摘要阅读 5 + 提取 5 + 核查 5 + 子主题分析 3 + 综合 1 + 大纲 1 + 写作 4 + 审阅 4 + 摘要 1 + 最终核对 1，合计约 33 次模型调用。此为设计假设，不是上游实测或费用承诺；章节工具循环、格式修复和重试另计，可能超过当前 50 次阶段上限。启动前显示预估与保留预算，接近上限时保存进度并给出调整条件，不新建根任务逃避累计计量。

论文资料不能共享给未批准的服务；只发送对应步骤需要的片段。暂停后不启动新请求；不能确认远端取消时按真实状态显示。图文、扫描件、公式、表格结论只能在已验证的解析/视觉能力范围内处理。

## 7. 开发前决策与调研退出条件

| 项目 | 当前建议 | 进入开发前要确定 |
| --- | --- | --- |
| 交付定位 | 可追溯综述/研究简报 | 用户确认它符合论文自动化的首个场景 |
| 学科与输入 | 不写死学科；少量开放论文 | 选定真实研究题目与一组人工标注样本，验证 arXiv 是否够用 |
| 来源和资料导入 | arXiv 起步，后续多来源；首版补充入口与两种缺失策略已确认 | 来源覆盖；补充交互按专门设计收口，不再将首版导入本身列为未决 |
| 工作流与模型 | 现有内核、可同模型承担各角色 | 通道输出结构的可用性、资料大小、上下文和总调用量 |
| 质量与产物 | Markdown/JSON，证据可回查 | 审阅不可用和关键检查失败的交付标识；人工抽查方法 |
| 模板与许可 | 分类参考、自行编写、固定版本 | 若要复制上游文本/代码，先明确许可；模板评测通过后才选默认 |

先完成这些规划与约束，并由用户另行决定进入开发；不把表中未决项悄悄改成代码默认值。

建议在固定的 5–10 篇人工核对资料集上预设任务：相关性、字段证据、缺失引用、相互矛盾结论、仅摘要、解析失败、材料注入、术语翻译、润色改变数值，以及超预算/重启。比较「简单阶段指令」与「结构化模板」的证据正确率、支持关系、失败识别和用量；格式/引用身份的硬性检查必须通过，语义质量阈值在标注数据和评分规则确认后设定，不能先拍一个准确率。
