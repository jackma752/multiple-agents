# P6 改进：从叙述综述转向论文理解与研究指导

日期：2026-10-30。来源：用户提供桌面 review.md，并指出缺少数学逻辑、研究方案、写论文指导，审阅成本高。本文件是对下一版的需求与验收定义，不表示以下功能已经实现。没有重新运行用户研究或修改原报告。

## 一、实际诊断

检查基线：E:/plug/agent-hub/.worktrees/p6-impl，feat/p6-paper-pipeline，HEAD 4784255。

1. 产品任务设定为 narrative literature review。templates.py 的 EXTRACT 只有 statement/kind/attribution/quote 等字段，没有符号、问题模型、假设、公式链或证明依赖；OUTLINE/SECTION 明确要求写叙述性综述。不是多加一句“详细推导”能彻底解决。
2. pipeline.py 的 select_chunks 按关键词计数选择片段，每篇输入预算 16,000 字符；有全文并成功解析时即标成 fulltext。全文可获取、抽样阅读、核心方法精读未区分。关键词不能保证定理、证明、跨页公式与附录完整。
3. 下游 _pack 只传提取的陈述和引文；EXTRACT 要求每条引文为一个片段内 20–300 字符。它适合来源定位，无法作为完整数学方法的唯一上下文。quote_in 只检查归一化后的引文包含关系，不能证明数学或解读正确。
4. phase_review 接收章节与同一证据包；revise 后仍用相同证据重写整个章节，当前 MAX_REVISIONS=1。流程有限次，但缺少“审阅问题→定向补读→更新证据→局部修复”的路径。具体本次 Token 分布未读取调用账本，不能凭报告定量归因。
5. SYNTHESIZE 只有主题总结、异同、当前样本空白，没有研究候选方案；导出把 gaps 放进“研究范围与局限”。缺少理解与研究指导两层产品。
6. 用户报告自身说“全文 5 篇”，又说只覆盖关键词片段；正文多次声明证明细节未提供。这说明深度不足，不能把可追溯引用或任务执行完成等同于科研用途验收通过。

## 二、明确产品目标

使用对象：没有论文发表经验、需要理解文献并逐步形成研究方案的用户。

应完成：研究问题理解→核心文献精读→数学推导重建→跨文献方法比较→可尝试的研究方案→验证→论文初稿→投稿准备与返修。

首屏交付应让用户知道：研究什么、为什么值得做、已有方法如何工作、可以改哪一步、怎样验证、下一步具体做什么。引用与证据为这些解释服务，不能替代解释。

保留“快速综述”作为可选模式；新增“读懂与推导”“形成研究方案”“推进论文”路径。理论论文不能硬套数据集/工程模型：问题模型应覆盖空间、公理、算子、命题、假设；应用论文则包括变量、目标、约束、数据与评价指标。

## 三、逐篇交付标准（核心优先级）

每篇核心论文提供：

1. 研究问题：旧结论解决什么、哪项假设限制使用、本文具体改变什么。说明与用户课题的关系。
2. 入门说明：先用直观语言解释问题，再给必要预备知识和符号表；不要堆叠未解释名词。
3. 数学设定：变量/对象/空间、定义域、关键假设及其作用、主定理或目标函数。公式用可渲染 LaTeX，保留源编号和 PDF 位置。
4. 方法全链：输入、变换、引理/定理依赖、关键不等式、推导每一步的理由、最终结论。证明跨页或引用附录时按依赖补读，不在关键跳步处用“由此可得”掩盖缺口。
5. 原文与教学重建分开：原文结论附位置；为帮助理解补出的步骤明确标注“本报告补充推导”；新猜想不冒充已证结果。原文有跳步、解析损坏或疑似错误时指出具体位置与影响。
6. 小例子与边界：给出可核对的手算例子；适用时提供可运行最小例子。理论研究核查假设必要性、反例、经典结果回收与等价变换；经验研究核查基线、指标和实验设置。
7. 学习出口：读者应能解释该方法、写出关键公式、说明结论成立的条件，并在一个小例子上复现关键步骤。

每篇论文不必同等投入。先完成低成本结构扫描，按主题相关性选核心篇进入精读；其余保留关联结论与定位。核心篇数与预计预算须在阶段批准中清楚展示。

## 四、综合总结必须输出研究方案

默认给出少量（例如 2–3 条）可比较候选，而非罗列“未来可推广”。每条包含：

- 明确研究问题；已有基线；要改变的一个关键点。
- 候选方法、公式或证明路线，说明为什么有可能成立。
- 理论路线：要证明的命题、需要的新引理、关键估计、反例搜索、是否只是已有结论的重新参数化。
- 算法路线：更新式、步骤/伪代码、终止条件、约束、计算成本、需要的收敛或稳定性论证。
- 验证路线：最小可行验证、对照/消融或理论核验、成功标准、失败后调整方向。
- 新手成本：先学哪些知识、需要什么工具与材料、难点、第一周可执行任务。
- 新颖性状态：先写“待查重的候选”，再按需检索相关工作；五篇里没出现不能称作整个领域空白。纯数学问题也不能把“换空间/换常数”自动当作有价值创新。

方法建议的依据、教学解释、待验证推测分开呈现。不能以现有提取字段禁止新方案，也不能把新方案写成文献已证结论。

## 五、审阅改成定向纠错

1. 检查对象：核心问题是否讲清、假设是否完整、数学链是否断裂、推导是否正确、来源是否匹配、方案是否可验证。不能只审引用，不审是否帮用户读懂。
2. 先做确定性检查：引用 ID、公式编号、变量定义完整性、产物存在性、预算。数值/符号检查仅覆盖其适用范围，不宣称有限算例证明一般定理。
3. 问题分类处理：
   - 原文材料不足：按问题定位补读相邻页、证明、附录；不要让写作模型反复改相同材料。
   - 数学矛盾/关键错误：修复涉及的公式链；无法解决时输出具体未解点，保留其他已完成部分。
   - 引用错配：局部替换或补证。
   - 文风/次要建议：一次汇总展示，默认不触发全节重写。
4. 只审变化的部分及其依赖。已核验基础材料和未改章节复用，模型/模板/输入/材料哈希变化时失效。审阅意见包含稳定问题 ID、受影响位置、关闭条件。
5. 将预算分成精读、数学解释、方案和审阅修复；展示实际用量。修复只在用户授权范围内，达到限额后保存问题清单和成果，不反复追求 PASS。额度不足不伪造通过，关闭审阅不等于质量变好。
6. 质量分别显示来源核对、数学重建、研究方案、语言表达状态。执行完成与质量通过分离；新手可阅读已验证部分，并明确知道哪一步仍需解决。

## 六、材料读取和页面设计

- 阅读深度改成“全文已获取 / 片段已读 / 核心方法已精读 / 推导已核查”，记录实际页与证明覆盖。兼容旧任务记录，禁止把旧 fulltext 批量冒充精读完成。
- 结构扫描定位 definitions/theorems/proofs/methods/appendix，再按依赖逐块读取。关键公式提取损坏应使用页面核对、可信源 LaTeX 或其他解析路径；不能猜测乱码。
- 报告分成“先读懂”“看完整推导”“比较方法”“研究方案”“下一步写论文”；符号释义紧邻公式。
- 核心结论和具体推导放正文；检索审计、引用映射、覆盖统计放附录/折叠详情。对结论有实质影响的缺口留在原位置，不通过隐藏风险制造可靠感。
- 结果可继续交互：“解释第 3→4 步”“验证这个例子”“把方案 A 变成实验清单”，复用已有研究状态，不从头检索五篇。

## 七、后续论文工作区（不是自动发表承诺）

研究方案确认后，形成可持续维护的项目：研究问题与贡献候选、理论证明笔记、实现/实验计划、实验记录、结果图表、论文草稿、参考文献、投稿准备与审稿意见处理。每份产物保留状态和下一步。

按文章类型给写作指导：理论论文是定义→引理→主定理→证明→例子/应用；经验研究是问题→相关工作→方法→实验→讨论。目标期刊/会议的格式和要求届时从其官方来源核对。不虚构结果、不杜撰参考文献，实际投稿由用户决定；方案成熟度来自验证，不能承诺录用。

## 八、实施顺序与验收

P6 改进 A（先修根因）：材料结构/阅读深度、逐篇方法与推导契约、定向补读、教学型报告。用固定公开核心论文检查：一篇完整推导、一道手算例子和关键假设检查。只做界面美化或加入“详细”提示词不算完成。

P6 改进 B：按问题局部审阅、材料缓存、成本和进度展示。用固定问题验证“缺证明→补证明材料”，不得原包重复整节重写；小问题不触发多轮；未改部分不重算。离线测试与真实输出质量验收分开，真实调用和预算仍按已批准的规则执行。

P6 改进 C：跨论文方法比较、2–3 条可验证方案、最小理论/算法验证和用户选择入口。仅“可考虑多值映射/公共不动点”不合格。

P6 改进 D：研究项目持续状态、论文草稿/实验或证明记录、投稿指导与返修流程。不是再次导出一份综述。

本轮报告验收锚点：用户应能在不从头自学全部文献的情况下，说清一个核心问题的设定，沿推导解释主要结论，完成一个例子，并据此选择一个具体研究候选及第一项验证任务。若缺原文证明或关键资料，先补材料；不消耗更多 Token 为薄弱摘要反复润色。
