# 引文与 Codex 钩子接入修复方案

2026-11-03，用户要求“按照这份调研结果，拟定好方案后去执行修好bug”。独立分支 `fix/citation-codex-083`，基线 `f2544cd`。不改 main、现有安装、旧研究材料或旧调用账本；不推送、合并或删除历史证据。

## 方案与约束

1. **来源定位**：仅在本次已发送、同一文档的材料中做精确匹配。声明位置匹配则保留；声明位置不匹配但只有一个其他精确位置时，记录声明位置、最终位置、原文范围及哈希后重定位；重复匹配或未知来源不猜测，不以模糊相似度放行。引文由后端从原文截取。
2. **完整诊断**：一次汇总所有来源错误，给出稳定单元 ID 和问题类型。已验证单元不因修复引用而重新生成。保留数学结构、依赖、必需来源和材料不足的检查，不静默丢弃关键单元。
3. **短编号与局部修复**：为新请求的来源提供后端确定的短编号，保留与真实片段的映射；新提示模板单独登记版本。来源修复只编辑被点名引用，仍经原阶段审批/预算与最大修复轮数。旧请求哈希、已批准快照和已完成研究不改。
4. **PDF 脚注**：先用现有解析器的版面信息核对真实失败 PDF。只有可验证的脚注区域才调整阅读顺序，保留脚注内容、PDF 原件及解析版本；正文、公式、页码不得凭模型猜测删改。旧文本不覆盖，无法确认时保留原抽取并报告，不接受拼接引文冒充连续原文。
5. **Codex**：修复隔离探针，先读回钩子定义、当前哈希和信任状态，再登记本轮已审核固定测试钩子的信任并重读；不使用绕过信任参数，不改用户登录目录。用真实固定 CLI + 本机合成 Provider 验证主线程、spawn_agent 及子任务工具的允许/拒绝和故障情况。只有确实满足受限配置的后端强制约束才开放该配置；无法故障拒绝时仍阻止严格准入，并明确剩余原因。新官方主分支能力不等价于本机固定版本已经通过。

## 验收

完整回归另发现已有的用量收尾竞争：`turn/completed` 已到、队列暂空时立即关闭传输，可能丢失随后到达的 Token 报告。本轮一并修复为最多 100ms 的收尾读取，不继续处理工具授权，不延长未知任务时限；迟到用量仍标为 partial，缺失仍为 unknown。增加用事件同步的回归用例，避免用固定睡眠掩盖竞争。

- 精确位置范围可回查；未知、跨文档、重复、改写、过短及缺失引用仍拒绝。新增结构不能绕过审批、资源规则、预算或变更已批准输入。
- 复核旧公开输出：三条错块能精确重定位，第四条保持旧证据不变并用新版 PDF 抽取单独验证。一次返回全部无法解决的引用，局部修复不改其他单元。
- 先完成相关离线回归、真实 CLI 合成协议检查；再使用已有账号路径做有界在线验收。没有可用严格配置的通道不降级或伪称通过。
- 本轮新增在线预算独立于旧账本：DeepSeek 最多 3 次、总计 24,000 Token、每次预留不超过 12,000；Codex 仅在准入通过后最多 2 次短任务，使用已有账户与 180 秒本地时限，记录实际用量，不宣称 provider 硬截断。Claude 本轮不追加已通过的在线重复测试。
- 真实证据保留忽略的 `var/`，只提交摘要、字节及 SHA-256。提交前展示暂存差异与实际检查结果。
