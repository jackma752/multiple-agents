# 论文讲解的公式导出与符号显示（0.7.1）

2026-10-30，用户用 Obsidian 打开 0.7.0 导出的 study.md，独立公式和符号表仍显示 LaTeX 字符。导出器给 latex 字段加了 `\[...\]`，定义字段则没有数学界定符；网页定义列表也直接使用纯文本。网页内已经安装 KaTeX，并不代表外部 Markdown 阅读器能识别相同写法。

## 修复

- 独立公式使用单独成行的 `$$`，行内符号使用 `$...$`。已有四种界定符转为通用 Markdown 数学写法，保守识别生成解释中的常见裸 TeX、下标变量和关系表达。
- 无花括号但具有合法单 token 参数的 `\tilde V_t`、`\mathcal F_t` 也能显示。不修补缺失的数学参数；孤立且缺参的命令保留原文。
- 代码、链接、文件路径、金额、已标记公式和原文引述保持原样。格式化器只改变界定符，不重写公式、研究结论或证据引文。
- 网页和 Markdown 导出共用 `unit_markdown`。`task_view.outcome.studies[*].units[*].display_markdown` 是临时响应字段，保存的结构化单元、后续追问、研究报告 JSON 和审批快照不加入该显示字段。
- 既有已完成任务可以重新导出，复用保存的结果，不重新调用模型。原安装中的旧导出文件不会被开发操作悄悄覆盖。

Markdown 本身不附带公式引擎；需用启用了数学显示的阅读器打开。此修复采用 Obsidian/Typora 常用的美元界定符，不承诺不支持数学的纯文本阅读器也能显示公式。

- 没有重跑全量测试、真实模型或研究任务；显示成功不等于数学推导已经正确。

## 维护入口

`papers/math_markdown.py` 负责纯格式化；`guidance_export.py` 组装单元；`service.task_view` 添加显示副本；`papers.html` 使用该显示副本并兼容旧响应。新增数学写法应增加明确的输入/输出用例，并用本地 KaTeX 实际检查；不能用正则改写数学含义。
