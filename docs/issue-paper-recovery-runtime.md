# 已付费回复接回原研究断点

用户指出离线恢复包不能代替修好项目。本轮在 `fix/paper-recover-paid` 上接续此任务，保留离线恢复证据，新增项目内的恢复入口；不启动在线模型，不改变用户阶段/审批/预算，不把引文校验当数学审阅。

## 契约与约束

- `GET /api/papers/{task}/recovery`：仅登录 approver 且研究归本人，列出当前阅读阶段未完成 study/study_patch 的已成功模型回复。每个候选绑定原 step/input_hash、原 invocation/snapshot/payload_hash、原审批发送材料、基础讲解与当前 checkpoint 的 fingerprint。较早完整回复也必须可以选择，不能只用最后一次。
- `POST /api/papers/{task}/recovery`：提交 step_id、invocation_id、fingerprint、client_request_id 和可选 corrections（unit_id/source_index/chunk_id/quote）。仅阶段 paused/blocked/stopped 且整树没有活动、排队或未知调用时允许。仅修已校验失败的原引用槽位，只能复制该槽原声明的已批准 chunk 内唯一精确原文；不得提交或修改讲解正文、公式、依赖、缺口。合并引用后重新执行完整结构和来源验证，有剩余错误不写入。
- 预览和恢复只处理原来已成功返回的回复，不能接受任意文件中的草稿替代。原模型 snapshot 必须仍匹配 payload_hash，原发送消息仍在审批输入中，chunk 的内容和页码仍匹配原审批材料，不能临时扩大材料范围。
- 写入同一模型 checkpoint 的已校验结果，保留所有调用 id/attempts/用量；另存一条幂等恢复审计记录，含旧步骤状态和结果，防止覆盖后无法追溯。重复请求不得重复写或创建调用，fingerprint 过期拒绝。
- 将讲解发布到原任务 outcome，finished=false、needs_review；原阶段保持原状态、规则/预算不变，不 kick 调度器。用户以后明确重新授权时复用恢复步骤，从后续数学审阅继续，不重新生成这份正文。
- UI 显示“恢复已生成回复（不调用模型）”，展示版本单元数、校验错误、失败引文和批准原文；来源纠正仅编辑引用。恢复成功后明确提示仍需数学复审和后续调用授权。

## 验证计划

离线模拟原模型成功而校验失败、较早完整/较晚残缺两版本、重复恢复、陈旧 fingerprint、跨用户/Agent、活动/未知调用、审批/原文变更、非法正文/引用修改、超过来源限制、预算保护和恢复后继续。验证所有恢复请求启动次数为 0，重授权后的首个新步骤为审阅，旧讲解/检索不重跑。实际原任务只恢复确定校验通过的回复，不发起在线模型。安装前保持原任务结束/暂停状态。

## 同一根因下的缺字段修复

历史第二篇已生成完整草稿，但两个假设 reason 字段缺失。新增 `TeachingFieldError` 保留原稿和命名字段，`research.reason-repair.v1` 仅返回这些字段的理由；每字段 1..4000 字符。提示只含待补单元、依赖的简要上下文及原批准的关联来源，不要求重发全稿。后端不接受正文、公式、依赖、来源、缺口等修改，补字段后仍执行完整校验和数学审阅；局部失败立即阻塞，不退回整篇生成。

旧接续任务在阅读阶段首次访问对应论文时，验证原成功回复的不可变 snapshot 和原发送分块、相同 PDF/分块内容，并将原稿迁移为当前断点的局部修复种子。保留旧历史步骤与用量，新调用只用于缺字段或随后暴露的引用问题，必须仍在用户新授权的阶段内。它不自动解除 32K 复核门禁、不重新授权或调用在线模型。
