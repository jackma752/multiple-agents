日期：2026-10-29。状态：需求与实施设计，尚未实现、尚未验收。

**当前边界（2026-10-29 用户补充）**：本阶段只做 P6 前期调研、功能规划和约束，不开始运行功能开发。上游源码调查见 [调研报告](p6-upstream-research.md)，提示词使用见 [模板设计](p6-academic-prompts.md)，固定提交和文件来源见 [来源清单](p6-research-sources.json)。完成规划收口后，由用户另行决定开始开发。

## 1. 产品目标与 P6 排期修订

在 Agent Hub 中增加「论文研究」入口：输入研究问题、年份、篇数、语言与预算，按用户批准的规则完成检索、筛选、阅读、证据整理、大纲、写作和检查，输出能逐项回查来源的综述与资料。

论文流水线作为 P6 首个业务功能优先推进；原 P6 的其他 Agent 扩展与安装配方继续保留，按需要接入，不以接完所有 Agent 为论文开发前置条件。论文角色不等于新的 Agent 产品：同一个已接入模型可以承担全部角色，也可由用户分配不同通道。

复用 Hub 的会话、调用快照、授权门禁、任务依赖、预算、用量、适配器和安装交付；新增论文领域的数据、工具、阶段状态和产物界面。首版采用内置可选模块，不先开发插件市场或任意代码插件加载器。

## 3. 用户操作与首版默认值

1. 进入「论文研究」，填写主题、年份、目标篇数、输出语言，并选择全文缺失时「可按现有资料继续」或「先等待补全文」；默认约 5 篇、中文输出，篇数与年份均可修改。
2. 选择已配置且可用的 Agent/模型。阅读、分析、写作可先共用一个通道，审阅可选第二通道；不强制安装多个 CLI。
3. 展示检索来源、PDF 下载范围、数据发送对象、输出位置、预算与完成条件；用户批准本次研究阶段。
4. 页面显示论文清单、排除原因、各篇阅读深度、证据卡片和流水线进度，允许暂停、停止及确认后恢复。
5. 阅读阶段统一汇总全部缺失全文的纳入论文，返回可复制的参考文献清单，依预选策略询问或等待；用户可上传、引用文件或提供文件地址。方案一首次 30 分钟未选择才默认继续；选择补充和方案二均无超时跳过；批次补充未齐时再询问是否继续补充。检索不足与证据不足另展示缺口，不静默补造材料。
6. 完成后展示综述、参考文献、证据对照与不足说明，可下载 Markdown 和结构化资料。

高级控制默认折叠，运行与失败信息采用普通用户能理解的文字。最初使用者不必手写协作计划。

## 4. 首版范围

包含：arXiv 检索、结果去重、摘要筛选、开放 PDF 下载与文本提取、两种全文缺失策略、汇总式补充请求、论文上传/引用/文件地址导入、逐篇结构化阅读、跨论文比较、大纲、逐节写作、引用和证据检查、Markdown/JSON 导出、持久化和恢复。

并非所有主题都有足够的 arXiv 文献。UI 明示首版来源范围，零结果应产生有解释的结果；OpenAlex 与 Semantic Scholar 在后续子阶段增加。

首版先使用带来源位置的文本分块和本地关键词检索，避免必须配置 embedding 才能开始。向量检索、embedding 供应商及索引版本迁移放在 P6.5；检索质量通过固定材料验证，不能把关键词检索与语义检索描述为相同能力。

后续范围：多来源、语义检索、扫描 PDF/OCR、公式和表格精读、Word/PDF 导出、更大规模综述。首版不实现网页爬取登录、付费墙绕过、自动投稿或代做实验；自动实验需要单独的执行与资源设计。

## 5. 接入现有内核的方法

建议新增位置（均为待实现）：

| 位置 | 职责 |
| --- | --- |
| `packages/contracts/agenthub/papers.py` | 任务、论文、证据、产物、资源授权与阶段结果契约 |
| `apps/worker/agenthub_kernel/papers/` | 流水线、来源连接器、解析、证据、引用、检查点和导出 |
| `apps/api/agenthub_rt/papers.py` | 经认证的任务、阶段、资料与下载接口 |
| 现有 `static/` 下论文页面资源 | 输入、进度、论文清单、证据与成果展示 |
| `tests/papers/` | 固定资料、离线端到端、领域检查及门禁回归 |

复用当前页面和安装体系，不为该功能另建 Vue 前端或第二个后台服务。先形成领域契约，再实施数据库迁移与接口；不在本轮提前声称公共接口已落地。

所有模型步骤都生成普通 InvocationSnapshot，经 PolicyService.consume 与 Worker 启动适配器。阅读模型、写作模型、审阅模型均计入同一个 root_task；重试、格式修复、补充阅读和汇总都计数计量，不允许模块直接调用模型 SDK 绕开预算和授权。

资料检索、PDF 下载、解析与文件写入是确定性工具步骤，不能因为不调用模型就绕过权限。现有 StageRules 只有命令前缀与文件修改规则，不足以表达 HTTP 来源、下载范围与论文资料发送：P6.1 必须补充有版本的资源授权契约，并在工具执行入口重新检查用户、阶段状态、规则哈希、目标来源及输出目录。不能把任意网络操作包装成已批准的聊天。

角色和模型绑定进入任务版本及调用快照。更改主题、候选来源、角色模型或资源权限，需要产生新版本和相应授权。暂停或停止后不启动新模型或新资源请求；已发出的远端请求如不能取消，保留真实状态。

## 6. 数据契约草案

| 对象 | 必要信息 |
| --- | --- |
| ResearchTask | task/root/conversation ID、主题、约束、语言、角色映射、规则版本、预算关联、状态、全文缺失策略与阅读关口 |
| PaperRecord | 本地稳定 ID、来源 ID、题名、作者、年份、DOI/URL、摘要、PDF 状态、内容哈希、来源合并信息 |
| TextChunk | paper ID、文档版本、分块 ID、提取方法、页码/章节/字符范围、文本哈希 |
| Evidence | paper/chunk ID、研究结论、原文片段、位置、局限、阅读深度、产生它的 invocation ID |
| SectionDraft | 大纲版本、章节 ID、正文、使用的 evidence ID、调用与审阅状态 |
| PipelineCheckpoint | 输入版本、规则哈希、步骤、项目/论文 ID、尝试次数、调用 ID、已提交产物和状态、补充请求/轮次/截止时间/剩余项 |
| ResearchArtifact | 产物类型、任务版本、受控相对路径、内容哈希、来源步骤、最终/草稿标记 |
| FulltextSupplementRequest / MissingFulltextItem / SupplementBatch | 策略、缺失题录、请求/决定/截止时间、每批文件与匹配/解析状态、剩余项及继续原因；详见专门设计 |

引用使用持久 paper/evidence ID，不用临时列表序号作为论文身份。没有可靠页码时标记未知，不从模型回复猜页码；摘要级、全文级证据分别展示。

去重优先 DOI、来源原生 ID/版本规则，再做规范化题名候选匹配；预印本与正式发表版本保留关联，避免只按相似标题错误合并。

导出至少包含 `review.md`、`references.json`、`evidence.json`、`research-report.json`；报告记录检索条件、排除原因、阅读深度、缺口、调用及用量摘要。原始运行证据与用户资料不进入 Git 或安装包。

## 7. 执行、恢复与用量

流水线：规划 → 检索 → 筛选 → 获取/解析 → 阅读 → 综合分析 → 大纲 → 逐节写作 → 检查/有限修订 → 导出。

步骤状态区分 pending/running/succeeded/failed/blocked/unknown；研究任务另有 waiting_input/paused/stopped/completed。等待用户补充不等同于手动暂停或执行未知；方案一首次未选择的 30 分钟截止持久化，方案二和用户已选择补充后不得超时跳过。领域状态映射现有内核状态，不能用一张步骤表代替授权和执行事实。

按论文与章节保存检查点：已成功获取、阅读或写作的相同版本产物不重复执行。幂等键包含任务版本、步骤、论文/章节、输入哈希及尝试标识；先记录调度意图和调用 ID，再发起外部副作用。

崩溃后先核对既有 invocation/工具记录；运行结果未知时不直接重发。输入、模型或解析版本变化只作废相关下游结果。恢复仍经过原有审批和预算入口。

现有自动阶段最多 50 次调用，且有单阶段目标与规则限制；逐篇阅读和写作可能耗尽上限。首版按真实步骤数预估并限制规模，额度不足时给出继续条件，不拆多个根任务逃避累计限制。不在论文模块私自改为无限。

模型返回的 Token 用量与归属沿用 usage ledger；不能取消的远端活动继续标示。后续 embedding 也必须有独立可审计调用、用量与预算关联；检索服务的请求额度与模型 Token 分开展示，不声称 Token 统计就是账单金额。

## 8. 工具与资料边界

论文内容、检索文本和模型输出都是资料，不能更改阶段规则、发起任意命令或授予自己权限。检索/下载有超时、大小、重试、来源与重定向检查；外部 URL 不能访问 loopback、内网地址或本机文件。任务资料和导出文件限定在经用户批准的目录。

PDF 按不可执行资料处理，解析失败保留原因；扫描件显示暂不支持 OCR。API 密钥复用宿主凭据存储，不放在论文记录、页面返回、日志或导出里。后续更换供应商时，明确哪些论文片段发送到哪个服务。

## 9. 质量与验收

确定性检查可以证明：引用 ID 存在、证据属于相应论文版本、原文片段确实存在于提取文本、定位能回查、参考文献来源可追溯。它不能单独证明论文结论正确或语义上支持写作结论；这部分用模型审阅加人工抽查，并保留争议和失败标记。

首版必须通过：

- 无阶段授权、授权失效、暂停、停止、预算不足时，新模型启动次数为 0；资源工具同样拒绝未授权请求。
- 5 篇固定论文离线跑通到导出；逐条校验 paper/evidence/chunk 关联、引用、阶段产物及用量归属。
- 注入重复检索、PDF 下载失败、解析空文本、无全文、格式错误、伪造证据、引用缺失与候选不足，结果有明确状态和原因。
- 两种全文缺失策略、一次性完整题录、首次 30 分钟默认继续、补充后取消倒计时、部分补充逐批询问、上传/引用/地址导入及恢复防重复均按 [专项验收](p6-fulltext-supplementation.md) 覆盖；此处仅规定验收，不代表已实现。
- 中途重启、重复提交、并发恢复不产生重复模型调用；未知状态阻止自动重放；已完成的论文和章节不重跑。
- 浏览器可查看来源、阅读深度、进度、暂停恢复、证据及下载；在窄屏仍可操作。
- 在用户指定的真实研究题目上做一次小规模完整验收，核对所有引用和核心结论；分别登记质量、时间、用量和人工修正，不以测试用例数量替代研究质量。
- 新安装包在干净环境能启用论文入口和必要解析依赖；不要求用户安装开发工具或独立 Node 前端。

真实外部检索、论文下载与付费模型回合，进入明确授权的验收步骤；日常测试使用本地固定材料和模拟适配器，不操作现有运行任务或用户凭据。

| 子阶段 | 交付 | 完成条件 |

| P6.4 工作台与安装交付 | 入口、设置预检、时间线、缺失题录/计时/批次补充选择、资料/证据/成品、暂停恢复、打包依赖 | 普通用户从安装到补充资料和导出完成验收 |
