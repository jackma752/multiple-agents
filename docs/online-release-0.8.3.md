- 带版本 PDF 地址首次 `unreachable:URLError`。缺失清单一次返回作者和题名；正式选择补充官方不带版本的 URL 后，由真实下载/补充校验取得 231,984 字节 PDF，SHA `6c24762a3f277fd120ed1adf34b01420ecf92f18ff6d1b5435fa0a09cb804ecb`。不是模拟下载，也未改数据库把失败伪装为成功。
- 精读生成 12 个单元，生产阶段实际触发一次 `research.source-repair.v1` 局部来源修复，33/33 引文通过。得到 3 个研究候选，创新性保持 unverified。
- 项目和演示实验记录各保存版本 1，23 项成果包内容哈希通过；重启后版本、结果和重新导出保留，零额外模型调用。演示数值不是论文实验。
- 暂停阶段无新增调用。初次测试脚本把在途调用只等 1 秒即判失败，修正后复用原调用、原阶段和原预算接续，没有重放已完成调用。

原流程完成时仍是 **needs_review**，有 3 个重大问题及资料缺口，因此原 `project-online-083/result.json` 的 `passed=false` 保留，没有事后改成 true。10 次真实调用，输入 79,642、输出 18,041，合计 **97,683 Token**。

## 实际缺陷与修复

旧代码只要有缺失资料且找不到新片段就直接退出修订，连已有资料可修正的数学/引用问题也不处理。已改为允许对点名的数学/引用问题作受限修订，带上其已有来源；纯资料缺失仍不为同一材料反复改写。没有新材料时禁止追加单元，后端保留旧 missing 与 incomplete，模型不能靠省略缺口把质量升为 passed。轮数、阶段授权和预算不变。

另减少模型上下文的重复审计字段：后端的来源哈希/偏移仍持久化，正文、公式、依赖、引文和页码保留；审阅、局部修订和研究候选提示不再重复发送 `source_location` 和历史 `citation_audit`。这是减少发送内容，不把推理等待时间称为传输性能提升。

## 用户追加额度后的局部在线复核

在独立 40,000 Token、最多 2 次调用的新账本中，用户明确批准对原结果修订并复核，不重新检索。一次局部修订修改点名单元，46/46 引文可回查，其他单元保持；一次复核接收修订单元、依赖公式与真实引文邻近窗口，未发现未解决的实质性问题。引文窗口之外、未提供的材料和形式化证明不在复核认证范围内。

新增输入 31,833、输出 5,852，共 **37,685 Token**，在追加额度内。首次修订实际 25,911 超过 20,000 启动预留，仍完整记账；第二次没有立即启动。压缩复核上下文后，保持总额 40,000 与最多 2 次不变，将第二次预留收窄为真实剩余 14,089，提示估算 11,405，实耗 11,774。没有扩额、忽略估算或把预留冒充 provider 硬截断。

**局部修复复测 `passed=true`，原完整项目质量仍保留 needs_review。** 资料中未定义的零分母等作者约定、完整提示词缺失不被编造；修订明确写出定义域/不可计算情形，已有资料不足项保留。原研究结果不被静默覆盖。软件功能与局部修复可以验收，不能据此宣称整篇论文的科学内容全部通过或自动具备出版质量。

本次在线总计 12 次调用、**135,368 Token**，在初始 100,000 加用户追加 40,000 内；两个新库均无运行/未知调用、并发占位为 0。此前 0.8.3 的 12,741 Token 引用定点测试是另一轮，未重复计入。
