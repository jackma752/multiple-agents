# 严格模式与传输优化

2026-11-02。用户在在线测试过程中要求“做完测试之后把执行模式中的严格模式修好，优化一下传输速度，然后过了测试”。基线在线修复 `e57089e`，独立分支 `fix/strict-transmission`。真实调用已达 9 次/52,866 Token，本阶段不再发模型请求，使用离线回归、已取得的真实数据及零模型网络测试。

严格模式：保留底层能力准入、逐次/阶段授权、工具审批、预算、暂停/停止、未知状态和精确引文检查。DeepSeek 文本 API 可严格运行；现有 Codex/Claude 真实通道仍声明严格控制未验证，不能通过改 allowed、自动切监督模式或移除校验来“修好”。论文预检应首先给出所选通道的实际模式准入，而不是让用户手动完成一个根本无法启动的严格回合；主/审阅任一不满足即拒绝建任务，模式只能由用户明确选择。公开预检增加每个所选通道的 mode_admissions。

新建研究初始默认主通道选择严格可用的真实通道（当前为 DeepSeek），没有真实可用通道时才考虑可用模拟通道。用户后续手动选主/审阅通道或模式时不自动改动选择。删除“当前 Codex 配置曾派生”的历史泛化文案：不同采用版本没有对应真实证据，只能说明当前适配器控制未验证。

传输：现有文本已按 0.2 秒/2000 字符合并写入，不重复实现。新增同进程事件提交后唤醒 SSE，保留跨进程 0.5 秒数据库轮询和重连游标；一次页面的 SSE 帧合并发送，不等所有任务完成。通知只加速读取，不能代替数据库事实、提交或用户授权。事务回滚不发送通知，订阅关闭后释放，跨会话仍走原鉴权。

论文 GET 支持 gzip 元数据传输，压缩与解压大小分别受原 max_bytes 约束，拒绝损坏/未知编码；每跳授权、TLS 校验、PDF/文本语义和原 URL/规则哈希不变。记录可选 wire_bytes/encoding，供本地验证压缩效果；不把减少字节数说成模型推理速度提升。

验证：严格/监督、真实不支持与离线模拟区分；无审批及超预算零启动；事件提交/回滚/多客户端/断线恢复/跨进程兜底与顺序； gzip 内容一致、解压膨胀/损坏/重定向/拒绝无网络。先测基线与优化后的本地通知延迟、发包数量及传输字节，实际数字登记。通过相关回归后再构建本地候选，不发布、不改现有安装。
